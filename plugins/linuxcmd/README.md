# Операции с файлами и путями — qtype_linuxcmd 0.2.1

Тип вопроса для Moodle 5.3 и семейство заданий элемента курса «Практикум».
Ученик читает легенду, текущий каталог и исходную структуру, затем вводит одну
команду. Реальный терминал и подготовка файлов на сервере не требуются.

Поддерживаются 10 операций: mkdir, mkdir -p, touch, cp для файла и каталога,
mv для переименования и перемещения, rmdir, rm для файла и непустого каталога.
Режимы путей: абсолютные, относительные, смешанные (источник относительный,
назначение абсолютное; для одного аргумента — относительный путь), обратные
смешанные (источник абсолютный, назначение относительное) и случайные.
В случайном режиме каждый аргумент независимо выбирается относительным с
вероятностью 2/3, абсолютным — 1/3. В «Практикуме» выбор автоматический,
в обычном редакторе вопросов ручные режимы сохранены.

Проверяется команда, разрешённые ключи, количество аргументов, их вид и путь
после разрешения относительно текущего каталога. Принимаются кавычки,
экранирование, ., .., повторные /, ключи --recursive, -r, -R и --parents, -p,
а также назначение в виде существующего каталога, если результат правильный.
Проверяется существование промежуточных каталогов. Регистр имён учитывается.
Неподдерживаемые ключи, цепочки команд, shell-подстановки и перенаправления
не принимаются. Это проверка ограниченной грамматики команд, не эмулятор Bash.
Команды учеников нигде не исполняются.

Сценарий генерируется при старте и целиком сохраняется в шаге question engine.
Восстановление и переоценка используют сохранённые данные. Шаблоны версионируются
и не меняют начатые попытки. Для новых правил генерации/проверки следует вводить
новую версию данных и ключа, сохраняя обработку старой версии.

## Установка

Архив qtype_linuxcmd.zip распакуйте в public/question/type: должен получиться
каталог public/question/type/linuxcmd. Для использования в «Практикуме» также
установите mod_practicum 0.4.0 и его зависимость qtype_ipv4 >= 0.4.0.
Выполните штатный upgrade Moodle и очистку кешей. Общий deploy.sh репозитория
обнаруживает новый компонент автоматически через manifest.json.

В редакторе обычного вопроса также доступны операция и вид путей.
Включены обработчики backup/restore, Moodle XML и Privacy API.

## Проверки

`php tools/check-linuxcmd.php` из корня репозитория запускает изолированные
проверки генерации, команд, путей, состояния и смешанного планирования.
Это не Moodle PHPUnit: классы окружения заменены заглушками.
Тесты Moodle находятся в tests/ и mod/practicum/tests/linux_lifecycle_test.php.
Фактически выполненные проверки и ограничения записаны в docs/VALIDATION.md.
