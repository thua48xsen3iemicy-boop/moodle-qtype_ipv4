# Практикум — mod_practicum 0.10.0 (alpha)

Отдельный элемент курса Moodle 5.3. Преподаватель выбирает «Добавить элемент или
ресурс → Практикум», задаёт блоки и сохраняет. Обычный тест создавать не нужно.

## Установка

1. Сохраните установленный `qtype_ipv4` (не ниже 0.4.0).
2. Установите `qtype_linuxcmd` 0.1.0 в `/var/www/moodle/public/question/type/linuxcmd`.
3. Скопируйте этот каталог в `/var/www/moodle/public/mod/practicum`.
4. Из `/var/www/moodle` выполните от пользователя PHP:

```sh
sudo -u www-data php admin/cli/upgrade.php --non-interactive
sudo -u www-data php admin/cli/purge_caches.php
```

Для сборки трёх отдельных ZIP из репозитория: `python3 tools/package.py`.
`dist/qtype_ipv4.zip` устанавливается в `public/question/type`,
`dist/qtype_linuxcmd.zip` — в `public/question/type`,
`dist/mod_practicum.zip` — в `public/mod`. Не устанавливайте весь репозиторий
как один модуль. Архив модуля имеет верхний каталог `practicum/`.

## Настройка

- Название, описание, режим.
- Тренировка: без срока и ограничения числа попыток; проверка ответа непосредственно
  в вопросе, объяснение после проверки. После проверки вопрос фиксируется; для
  повторной тренировки запускается новая попытка. В журнал оценок результат не идёт.
- Контрольная: необязательный лимит времени и число попыток (0 — без ограничения).
  Обратная связь после сдачи. В журнал идёт лучший результат контрольных, шкала 0–100.
- Блоки: вид задания, число и параметры. «Добавить блок» добавляет ещё блок;
  количество 0 исключает блок. Суммарно 1–100 заданий.
- В поле «Вид задания» доступны все 12 вариантов IPv4: адрес сети, broadcast,
  первый/последний адрес узла, префикс → маска и маска → префикс, одна подсеть,
  назначаемость адреса, следующий/предыдущий IPv4, следующая подсеть, число узлов.
- Для каждого блока можно выбрать несколько допустимых префиксов /1–/30
  (Ctrl/Cmd для нескольких значений). По умолчанию /8, /16, /24.
  Префиксы выбираются независимо случайно; балансировка не применяется.
- Для Linux доступны 10 операций: создание каталога, вложенных каталогов и файла;
  копирование файла и каталога; переименование и перемещение; удаление пустого
  каталога, файла и каталога с содержимым. Вид каждого пути выбирается случайно,
  чаще относительный. Поддерживаются оба смешанных сочетания источника и назначения.
- Linux-задания содержат текущий каталог и исходную структуру. Ученик вводит одну
  команду; проверяется смысл операции и пути, принимаются эквивалентные записи.
  Команды нигде не исполняются. Linux и IPv4 можно смешивать в одной попытке.
- В заданиях «Одна подсеть» и «Назначаемость адреса» ответ выбирается
  переключателем **Да / Нет**. В остальных заданиях — ручной ввод:
  префикс с `/` или без, следующая подсеть с префиксом, число узлов числом.
- Для смешанного набора добавьте блок для каждого нужного вида и задайте количество.
  В обучающей обратной связи используется объяснение именно выбранной операции.

Набор генерируется при начале попытки. План, режим, срок, IP и ответы сохраняются.
Обновление страницы не генерирует новое условие. Изменение настроек влияет на новые
попытки. Шаблоны вопросов переиспользуются по настройкам; состояния попыток раздельны.

Нажимайте «Сохранить ответы» перед уходом со страницы. Автосохранения в этой
первой версии нет. По истечении срока принимаются только ранее сохранённые ответы;
страница автоматически перезагружается для отображения результата. Незавершённые
просроченные попытки также обрабатывает штатный cron Moodle (задача каждую минуту).
Работающий cron обязателен для завершения попыток закрывших браузер студентов.

Преподаватель видит список всех попыток, студент — своих. Завершённую попытку
можно просмотреть. Поддерживаются резервное копирование с попытками и Privacy API.

## Расширение и границы версии

`classes/local/task_type.php` — контракт семейства заданий, `registry.php` — реестр,
`blueprint.php` — планировщик. Сейчас разные блоки могут иметь разные настройки IPv4.
Реальные терминалы и VM ещё не реализованы. Контракт будущего изолированного
бэкенда и правила безопасности описаны в `docs/ARCHITECTURE.md` репозитория.

Alpha-версия: нет миграции обычных тестов в практикумы, автосохранения,
адаптивных повторов внутри одного вопроса, специальных исключений по времени,
расширенной аналитики и Moodle Mobile. Существующие тесты с qtype_ipv4 продолжают
работать отдельно. Полный набор возможностей mod_quiz здесь не воспроизводится.

## Обновление с 0.1.0

Установите qtype_ipv4 0.3.0 и mod_practicum 0.2.1, выполните штатный upgrade
и очистку кешей (либо запустите корневой deploy.sh из актуального репозитория).
Схема таблиц не меняется. Старые блоки и id `ipv4_network` сохранены; сохранённые
попытки используют прежние question usages. Новые шаблоны имеют ключ v2,
включающий тип задания и префиксы, и не перезаписывают старые шаблоны.

## Обновление 0.2.1

Новые попытки логических заданий используют выбор Да/Нет. Начатые до обновления
попытки сохраняют ручной ввод и прежние ответы. Старые шаблоны не изменяются;
новые логические шаблоны используют отдельные ключи v3. Изменений таблиц нет.
После обновления через deploy.sh начните новую попытку для нового интерфейса.

## Версия 0.3.0: команды ip и диагностика

Обновляйте вместе с qtype_ipv4 0.4.0 (2026110903). В блоках доступны 41 вид:
12 прежних IPv4 и 29 командных/диагностических заданий. Поле вида задания
поддерживает поиск по теме и названию. Команды используют ручной ввод, составные
ответы — несколько строк; Да/Нет остаются кнопками. Условия существующих попыток
и идентификаторы старых шаблонов не меняются. Команды на сервере не выполняются;
поддерживается ограниченный синтаксис, описанный в корневом README.

## Обновление 0.4.0: Linux

Добавлена обязательная зависимость qtype_linuxcmd 0.1.0. Сборка создаёт три ZIP;
корневой deploy.sh устанавливает их по общему manifest.json. Новый тип вопроса
создаёт свою таблицу настроек; таблицы модуля и IPv4 не меняются. Старые настройки,
шаблоны и начатые попытки IPv4 сохраняются. После обновления добавьте в настройках
элемента курса Linux-блоки и выберите вид путей. Для новых условий начните новую
попытку. Проверки этой версии и ограничения — в docs/VALIDATION.md репозитория.

### Быстрый выбор вопросов

При добавлении практикума можно выбрать режим:

- **Поровну по выбранным темам** — мультивыбор тем и одно количество для каждой.
- **Случайно из выбранных тем** — мультивыбор (или все типы) и общее количество,
  например 6 или 10. Тип каждого задания выбирается независимо; темы могут
  повторяться или не попасть в конкретную попытку.
- **Количество по каждой теме** — прежние блоки с отдельными настройками.

Суммарно допускается 1–100 вопросов. В быстрых режимах префиксы общие для IPv4.
Вид каждого Linux-пути выбирается автоматически, чаще относительный. Изменение настроек применяется к новым попыткам.

## Обновление 0.5.1: автоматический выбор путей

Выбор вида Linux-путей убран из всех режимов настройки активности. После
сохранения формы новые попытки получают случайные пути: каждый аргумент
независимо относительный с вероятностью 2/3 или абсолютный с вероятностью 1/3.
Доступны оба смешанных сочетания, включая абсолютный источник и относительное
назначение. Условие явно указывает требуемые виды путей, исходная структура
сохранена. Нет квот или гарантии всех сочетаний в одной попытке.
Старые конфигурации до пересохранения и начатые попытки сохраняют прежние правила.
Требуется qtype_linuxcmd >= 0.2.0 (2026111001); схема БД не меняется.

## Обновление 0.6.0: выбор категорий

Семейство заданий «Linux» переименовано в «Операции с файлами и путями».
В режимах «Поровну» и «Случайно» появились флажки категорий:
подсети, адреса и интерфейсы, маршрутизация, виртуальные интерфейсы,
диагностика, операции с файлами и путями. Одним флажком включаются все типы
в категории. Можно отметить несколько категорий и добавить отдельные типы;
повторы учитываются один раз. Выбор сохраняется при редактировании.

«Поровну» задаёт количество на каждый тип внутри выбранных категорий;
«Случайно» — общее количество из объединённого набора типов. Сохраняется лимит
100 вопросов. Новые типы, зарегистрированные в категории, включаются при
следующем сохранении настроек. Начатые попытки и старые блоки не меняются.
Технические идентификаторы плагинов прежние. Требуется qtype_linuxcmd 0.2.1.

## Обновление 0.6.1: возврат к проверенному вопросу

В тренировке после «Проверить» страница открывается у проверяемого вопроса,
а не у первого. Перезагрузка остаётся штатной; JavaScript не требуется.
После завершения попытки открывается начало страницы с результатом.

## Обновление 0.7.0: все типы категории без повторов

Выберите режим **«По одному вопросу каждого типа (без повторов)»**, затем отметьте
нужные категории. Например, «Подсети — типов: 12» добавляет 12 заданий:
по одному каждого типа. Количество вводить не нужно. Можно объединить несколько
категорий и отдельные типы; совпадения добавляются только один раз. Порядок
заданий перемешивается, а адреса/маски генерируются как прежде из допустимых
префиксов. Это охват всех типов, а не всех возможных IP-адресов и масок.

В режиме «Поровну» число означает количество **на каждый тип**; значение 1
тоже даёт полный охват. В режиме «Случайно» число означает **общее** количество
с выбором типов с возвращением: повторы и пропуски возможны. Старые настройки
этих режимов и начатые попытки не меняются. Лимит — 100 вопросов на попытку.

## Обновление 0.10.0: первая учебная тема

1. Добавьте в курс отдельный элемент «Практикум» и задайте название.
2. В «Содержание активности» выберите **«Основы IPv4: предыдущий и следующий адрес»**.
3. Укажите число заданий каждого вида: по умолчанию 4 + 4; допустимо 1–50
   каждого вида. Выберите «Тренировка» для подготовки с проверкой ответов.
4. Сохраните. Студент сначала увидит теорию, затем кнопку начала практики.

Теория объясняет октеты, диапазон 0–255, перенос и заимствование через несколько
октетов, крайние значения и отличие порядка адресов от назначаемости узлам.
Есть разобранные примеры и самопроверка. В тренировке теорию можно развернуть
прямо над заданиями. Используются существующие вопросы на следующий/предыдущий
адрес с ручным ответом; условия генерируются при начале попытки как прежде.
Разные случаи переходов не гарантированы в каждой отдельной попытке.

Это отдельная активность курса на базе того же модуля, новый плагин устанавливать
не нужно. Для прежней настройки блоков выберите «Свой набор заданий».
Настройки темы восстанавливаются при редактировании; начатые попытки сохраняют
свои вопросы и ссылку на версию теории. Обновление модуля штатное, без миграции БД.

Можно отдельно добавить такую же тему в режиме контрольной; теория видна перед
началом и после завершения, но не встроена в незавершённую контрольную попытку.
В этой первой версии одна активность использует один режим: объединённой цепочки
«тренировка → итоговый тест», автоматического зачёта темы и открытия следующей
активности пока нет. Теория встроенная, редактирование преподавателем не добавлено.

## Обновление 0.7.1: обязательный префикс в адресе сети

Для новых попыток «Найти адрес сети» требуется ответ `адрес/префикс`, например
`192.168.1.0/24`. Адрес без префикса не принимается; проверяются обе части.
Подсказки и эталон обновлены. Сохранённые попытки сохраняют старый формат.
Нужен qtype_ipv4 0.5.0 (2026111001); изменений таблиц нет.

## Обновление 0.8.0: несколько типов в одном блоке

В режиме «Количество по каждой теме» поле «Вид задания» поддерживает мультивыбор.
Количество применяется к **каждому** выбранному типу: 3 типа по 5 вопросов дают
15 вопросов. Для других количеств или префиксов добавьте ещё один блок.
При редактировании выбранные типы остаются сгруппированы по своим блокам.

В одном блоке можно сочетать IPv4 и операции с файлами. Префиксы применяются
только к заданиям IPv4. Повторы типа внутри блока исключаются; в разных блоках
один тип может встречаться с разными настройками. Старые блоки с одним типом и
начатые попытки сохраняются. Лимит 100 вопросов проверяется после раскрытия
мультивыбора. Изменений таблиц и qtype нет.

## Права доступа (0.9.0)

Новая категория «Права доступа в Linux» содержит 17 видов заданий: chown,
chgrp, chmod, SUID/SGID/sticky bit, перевод числовых и буквенных прав,
значения r/w/x для файлов и каталогов. Ответ — команда либо указанная в
условии короткая запись. ACL оставлены для отдельного модуля. Требуется
qtype_linuxcmd >= 0.3.0; обновите оба компонента и выполните upgrade Moodle.
Категория файлов и путей по-прежнему содержит исходные 10 видов заданий.
