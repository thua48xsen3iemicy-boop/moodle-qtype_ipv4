# Репозиторий генераторов и «Практикума» для Moodle 5.3

Новый отдельный элемент курса находится в **`mod/practicum`**. Установка и
использование: [mod/practicum/README.md](mod/practicum/README.md).
Он поддерживает тренировку и контрольную, блоки заданий и ручной ввод IPv4.

Для агентов: начните с [AGENTS.md](AGENTS.md). Архитектура и передача работы —
в `docs/`. Сборка двух отдельных ZIP: `python3 tools/package.py`.

Корень репозитория сохраняет совместимость с установленным `qtype_ipv4`.
Ниже — документация этого типа вопроса и прежнего массового заполнения тестов.

# qtype_ipv4 — IPv4 и подсети

Версия **0.4.1 (beta)** типа вопроса для **Moodle 5.3**.

## Команды ip и диагностика: версия 0.4.0

Доступен общий каталог **41 задания**: 12 прежних вариантов IPv4 и 29 новых
заданий на адресацию, состояние и MTU интерфейсов, маршрутизацию, виртуальные
интерфейсы и диагностику. Сохранены префиксы /1–/30, логические ответы Да/Нет
и все прежние условия попыток. Команды и диагностика используют свободный ввод.

В редакторе вопроса и блоках «Практикума» работает поиск по теме и названию.
Массовое добавление в обычный тест использует сворачиваемые группы с флажками.
Общее количество делится между выбранными видами (минимум по одному каждого);
префиксы при этом по-прежнему выбираются независимо, без квот.
Категории в банке обычного теста создаются по темам и повторно используются.
Настройки префиксов и выбора вариантов относятся к вычислениям IPv4.

- Адреса и интерфейсы: добавить/удалить IPv4, дополнительный адрес, IPv6, up/down, MTU.
- Маршруты: default gateway, сеть, узел, удаление, замена шлюза, метрика, таблица, blackhole.
- Виртуальные интерфейсы: dummy, veth, VLAN, bridge, включение в мост, удаление,
  цепочка «создать VLAN → назначить адрес → включить».
- Диагностика: определить адрес, префикс, default gateway, выбрать наиболее длинный
  совпадающий маршрут, исправить состояние, шлюз или неверный префикс.

Проверяется ограниченная учебная грамматика, команды учащегося не выполняются.
Принимаются сокращения объектов и действий (`ip a a`, `ip l s`, `ip r a`),
допустимые перестановки аргументов, необязательный `sudo`, согласованные `-4`/`-6`,
`default`/`0.0.0.0/0`, адрес узла с `/32` и без, эквивалентные записи IPv6.
`dev`, `via`, `local`, `to`, `name`, `up`, `down`, `mtu` пишутся полностью.
Поддерживаются `metric`/`priority`/`preference`, явный `table main` и egress dev
из условия. Для замены существующего шлюза подходят `replace` и `change/chg`.
Составные ответы вводятся по одной команде на строку в указанном порядке.
Неизвестные и лишние атрибуты, операторы оболочки, нестандартные имена таблиц,
десятичные маски вместо префикса и произвольные альтернативные цепочки не
поддерживаются. Полная совместимость со всем синтаксисом iproute2 не заявляется.

Обновляйте **оба плагина** из одного коммита через `deploy.sh` либо двумя ZIP
из `python3 tools/package.py`. qtype_ipv4 0.4.0 имеет версию БД `2026110903`,
mod_practicum 0.3.0 требует её. Прежний API `exercise::TYPES` сохранён для старого
«Практикума»; расширенный каталог доступен как `exercise::ALL_TYPES`.
Не понижайте зависимости и не меняйте только число версии в старых файлах.

## Доступные задания

При создании вопроса или массовом добавлении в тест выберите поле **«Тип задания»**:

| Тип | Пример ответа |
| --- | --- |
| Адрес сети | `10.37.0.0` для `10.37.19.214/16` |
| Broadcast | `10.37.19.255` для `10.37.19.214/24` |
| Первый адрес узла | `10.37.19.1` для `10.37.19.0/24` |
| Последний адрес узла | `10.37.19.254` для `10.37.19.0/24` |
| Префикс → маска | `255.255.0.0` для `/16` |
| Маска → префикс | `/16` для `255.255.0.0` |
| Два адреса в одной подсети | Да / Нет |
| Возможность назначения адреса узлу | Да / Нет; `10.37.19.0` допустим в `10.37.0.0/16` |
| Следующий IPv4 | `10.37.20.0` после `10.37.19.255` |
| Предыдущий IPv4 | `10.37.19.255` перед `10.37.20.0` |
| Следующая подсеть | `10.37.19.128/26` после `10.37.19.64/26` |
| Число адресов для узлов | `62` для `/26` |

Девять семейств заданий представлены двенадцатью пунктами: направления перевода,
первый/последний узел и следующий/предыдущий IP выбираются отдельно.
Поддерживаются префиксы **/1–/30**, включая неоктетные, например /25, /26, /27.
Правило подсчёта узлов: `2^(32 − префикс) − 2`, без сетевого и broadcast-адреса.
/31 и /32 исключены, поскольку у них другие правила использования адресов.
По умолчанию отмечены /8, /16, /24.

## Установка и обновление

Требуется рабочая установка Moodle 5.3 с поддерживаемыми PHP и СУБД.

1. Поместите файлы плагина в `public/question/type/ipv4` относительно корня Moodle.
   Файл `version.php` должен лежать прямо в этой папке. Компонент — `qtype_ipv4`.
   Не копируйте `.git`, `work` и сторонние зависимости.
2. Откройте «Администрирование → Уведомления» либо выполните из корня Moodle:

   ```sh
   php admin/cli/upgrade.php --non-interactive
   php admin/cli/purge_caches.php
   ```

Запускайте CLI от пользователя веб-сервера. При обновлении с 0.1.0/0.2.0
обязательно скопируйте новый `db/upgrade.php`: он расширяет поле префиксов
и добавляет тип задания. Старым вопросам присваивается тип «Адрес сети».
Старые сохранённые попытки без поля типа продолжают читаться как задания на адрес сети.

## Добавление в тест курса

1. Создайте обычную активность **«Тест»** в нужном курсе.
2. В меню курса (при необходимости в разделе «Ещё») выберите **«Добавить IPv4 в тест»**.
3. Выберите тест, **виды заданий в тематических группах**, количество (1–100, по умолчанию 15),
   допустимые префиксы и режим ответа.
4. Нажмите **«Готово — добавить вопросы»**. Откроется штатный редактор теста.
5. Выбранные виды добавляются одним смешанным набором.

Прямая ссылка: `/question/type/ipv4/generate.php?courseid=ID_КУРСА`.
Типы выбираются внутри плагина вопросов **«IPv4 и подсети»**;
они не являются отдельными активностями в меню «Добавить элемент или ресурс».
Один вопрос вручную создаётся в банке вопросов через «IPv4 и подсети»:
выберите тип, префиксы и режим, сохраните и добавьте в тест.
Конкретное условие плагин добавляет сам; достаточно общего текста
«Решите задание по IPv4».

Одна отправка формы добавляет выбранный набор видов заданий. Существующие вопросы
сохраняются. У каждого нового вопроса вес 1 балл, максимальная оценка теста
остаётся заданной преподавателем. Изменять состав теста с реальными попытками
учащихся нельзя. Предварительные просмотры преподавателя этому не мешают.
Создание выполняется одной транзакцией с проверкой прав и блокировкой теста.

## Ответы и состояние попытки

Расчётные типы IPv4 поддерживают ручной ввод или варианты ответа.
У логических заданий два варианта «Да / Нет», у остальных — четыре.
Для ручного ввода логических ответов принимаются `Да`, `Нет`, `yes`, `no`
без учёта регистра. Префикс принимается как `/26` или `26`.
Следующую подсеть нужно вводить с префиксом: `10.37.19.128/26`.
Число узлов — целое десятичное число, без пояснений.
IPv4 и маски вводятся четырьмя октетами, без ведущих нулей.
Пробелы по краям ответа игнорируются. Частичного балла нет.

Шаблоны хранят настройки; IP, префикс, дополнительные адреса, тип, режим
и порядок вариантов генерируются при начале попытки и сохраняются в `_ipv4`
первого шага движка вопросов Moodle. Обновление страницы, продолжение,
просмотр и переоценка используют сохранённые данные. Новая попытка генерирует
новые условия; случайные совпадения возможны. При настройке
«Каждая попытка основывается на предыдущей» действует штатное продолжение Moodle.

Расчёты выполняются по октетам без `ip2long`; сетевых запросов к учебным IP нет.
Настройки сохраняются в `qtype_ipv4_options`, поддерживаются Moodle XML
и стандартное резервное копирование/восстановление, включая старые данные
без типа задания. Варианты принадлежат попытке, а не `question_answers`.
Оценки, доступ и видимость отзывов регулирует Moodle.
Русские и английские строки входят в плагин.

## Проверки

Используется PHPUnit Moodle 5.3 с **отдельными тестовой БД и каталогом данных**.
Не указывайте рабочие таблицы или рабочий каталог: инициализация удаляет тестовые данные.
После настройки `$CFG->phpunit_prefix` и `$CFG->phpunit_dataroot` из корня Moodle:

```sh
composer install
php public/admin/tool/phpunit/cli/init.php
vendor/bin/phpunit --testsuite qtype_ipv4_testsuite
```

Тесты покрывают вычисления, все типы и префиксы, форматы ответов, состояние
и оценивание, создание вопросов, Moodle XML и резервное копирование.
Фактически выполненные проверки и ограничения описаны в [TESTING.md](TESTING.md).
