# qtype_ipv4 — IPv4 и подсети

Версия 0.2.0 (beta) типа вопроса для **Moodle 5.3**.
Задание: «Определите адрес сети по IPv4-адресу и префиксу».

## Установка

Требуется штатная рабочая установка Moodle 5.3 с поддерживаемыми PHP и СУБД.

1. Поместите содержимое этого репозитория в `public/question/type/ipv4`
   относительно корня Moodle 5.3. Файл `version.php` должен находиться прямо в
   этой папке. Каталог называется **ipv4**, компонент — **qtype_ipv4**.
   Служебную папку `work/` копировать не нужно.
2. Откройте «Администрирование → Уведомления» и выполните установку либо запустите
   из корня Moodle: `php admin/cli/upgrade.php --non-interactive`.
3. При необходимости очистите кеш: `php admin/cli/purge_caches.php`.

Русский и английский языки входят в плагин. Русские строки используются при
выборе русского языка в Moodle.

## Автоматическое заполнение теста — рекомендуемый способ

1. Создайте обычный тест Moodle в нужном курсе (или используйте уже созданный).
2. Откройте главную страницу **курса**. В меню курса, при необходимости в разделе
   **«Ещё»**, выберите **«Добавить IPv4 в тест»**.
3. Выберите тест, укажите количество (по умолчанию **15**, допустимо от 1 до 100),
   допустимые префиксы и режим ответа.
4. Нажмите **«Готово — добавить вопросы»**. Откроется штатный редактор вопросов
   теста: все выбранные задания уже добавлены. Создавать вопросы по одному не нужно.

Прямая ссылка, если тема скрывает пункт меню:
`https://ваш-moodle/question/type/ipv4/generate.php?courseid=ID_КУРСА`.
ID курса виден в адресе его главной страницы: `/course/view.php?id=...`.
Форма показывает только тесты текущего курса, для которых у преподавателя есть
права на управление тестом, создание и использование вопросов.

Сразу создаются только **шаблоны** вопросов с настройками. В конкретные IP-адреса,
префиксы и варианты они превращаются **при старте попытки учащегося**.
У каждого студента и каждой новой попытки будет свой случайный набор; при
продолжении или обновлении страницы сохраняется прежний. Строгая уникальность
между всеми студентами не гарантируется: случайные совпадения возможны.

Вопросы хранятся в собственном банке выбранного теста Moodle и добавляются в его
конец. Существующие вопросы сохраняются. Каждое новое задание имеет вес 1 балл;
максимальная оценка теста остаётся установленной преподавателем. Повторная
отправка новой формы добавляет ещё указанное количество вопросов.

Если в тесте есть реальные попытки учащихся, менять его состав нельзя. Создайте
новый тест. Попытки предварительного просмотра преподавателя этому не мешают.
Создание всего набора выполняется в одной транзакции, сумма баллов обновляется
через штатный API Moodle.

## Обновление с 0.1.0

Обновите содержимое `public/question/type/ipv4` файлами версии 0.2.0, включая
`generate.php`, `classes/batch_service.php`, `classes/form/generate_form.php`,
`classes/navigation.php` и `db/hooks.php`. Затем выполните обычный апгрейд Moodle
и очистку кеша. Запускайте PHP CLI от пользователя PHP/веб-сервера, например:

```sh
sudo -u www-data php admin/cli/upgrade.php --non-interactive
sudo -u www-data php admin/cli/purge_caches.php
```

Подставьте пользователя вашего PHP вместо `www-data`. Новых таблиц для этой
версии нет; апгрейд регистрирует пункт меню. Ранее созданные вопросы и попытки
продолжают работать.

## Создание одного вопроса вручную и проверка в тесте

1. В курсе откройте банк вопросов, создайте вопрос типа **«IPv4 и подсети»**.
2. Укажите название и текст, например «Вычислите адрес сети». Плагин самостоятельно
   добавит конкретный IPv4-адрес и префикс; подстановки в тексте не требуются.
3. Отметьте один или несколько префиксов: `/8`, `/16`, `/24`. Выбор пустого набора
   запрещён. Выберите ручной ввод или один из четырёх вариантов. Сохраните вопрос.
4. Добавьте вопрос в обычный тест Moodle с отложенным отзывом и разрешите
   несколько попыток. Проверьте оба режима, создав два вопроса.
5. Начните попытку как учащийся. Запишите IP, префикс и порядок вариантов.
   Ответьте, перейдите на другую страницу теста, обновите страницу и продолжите
   попытку после выхода и повторного входа. Условие, порядок и сохранённый ответ
   должны остаться прежними. Ответ сохраняется штатной отправкой страницы или
   автосохранением Moodle; несохранённый текст подчиняется обычным правилам Moodle.
6. Завершите попытку. Правильный адрес сети получает полный балл, другой корректный
   IPv4 — ноль. При просмотре результата условие и варианты должны совпадать с
   исходными. Видимость оценки, правильного ответа и общего отзыва задаётся
   стандартными настройками просмотра теста.
7. В ручном режиме попробуйте ` 10.37.19.0 ` (пробелы по краям допускаются),
   `10.37.19.0/24`, `300.1.2.3`, `10.37.19`, `010.37.19.0` (ошибка формата).
   В режиме отложенного отзыва незавершённый/невалидный ответ при окончательной
   сдаче обрабатывается штатным поведением Moodle без положительного балла.
8. Начните новую попытку: условие генерируется заново. Случайное совпадение возможно.
   Если включено «Каждая попытка основывается на предыдущей», действует штатное
   продолжение Moodle с прежним состоянием вопроса.

## Генерация и состояние

- При старте выбирается случайный разрешённый префикс и синтетический IPv4
  с ненулевой частью узла. Адреса служат только примерами: сетевые запросы к ним
  не выполняются. Первый октет 1–223, кроме 127, остальные — 1–254.
- Расчёт выполняется по октетам без зависимости от знака `ip2long` и разрядности PHP.
- В наборе четыре различных адреса: один правильный, соседняя сеть того же
  префикса и два адреса внутри исходной сети. Два внутренних дистрактора выбираются
  из первого узла, broadcast и границы при ошибочном более длинном префиксе
  (`/9`, `/17`, `/25`). Комбинации и порядок случайно меняются.
- Для `/24` ровно два неправильных варианта сохраняют первые три октета; третий
  представляет другую сеть `/24` и заканчивается `.0`. Для `/16` и `/8` действует
  аналогичное правило на границе двух и одного октета. У крайних значений октета
  выбирается существующая соседняя сеть без переполнения.
- IP, префикс, режим и упорядоченный массив вариантов записываются в `_ipv4`
  первого `question_attempt_step`. `apply_attempt_state()` только восстанавливает
  эти данные. Правильный адрес вычисляется из сохранённого условия.
- Оба режима используют `question_graded_automatically`, штатные поведение,
  хранение ответов, права доступа, оценки и параметры просмотра Moodle.
- Параметры вопроса хранятся в `qtype_ipv4_options`. Поддерживаются стандартные
  резервное копирование/восстановление и Moodle XML. Генерируемые варианты
  принадлежат попытке и не создают фиксированные записи `question_answers`.
- IPv4 принимается в канонической десятичной записи без префикса и ведущих нулей;
  пробелы по краям игнорируются. Частичного балла нет.

## Автоматические тесты

Используется штатная инфраструктура PHPUnit Moodle 5.3, отдельная тестовая БД
и отдельный каталог данных. **Не указывайте рабочие таблицы/каталог данных**
в настройках PHPUnit: инициализация тестов очищает тестовые данные.

Из корня Moodle после настройки `$CFG->phpunit_prefix` и `$CFG->phpunit_dataroot`:

```sh
composer install
php public/admin/tool/phpunit/cli/init.php
vendor/bin/phpunit --testsuite qtype_ipv4_testsuite
```

После добавления нового плагина повторите инициализацию PHPUnit.
Тесты проверяют расчёт сети, валидацию, ограничения префиксов, уникальность и
состав вариантов на всех трёх префиксах, крайние октеты, смену комбинаций,
оценивание обоих режимов и сохранение/загрузку/продолжение/завершение/переоценку
попытки через настоящую БД Moodle, настройки формы, Moodle XML и резервное
копирование/восстановление банка вопросов.

Фактически выполненные проверки и ограничения среды описаны в [TESTING.md](TESTING.md).

## English

Moodle 5.3 question type **IPv4 and subnets**. Install into
`public/question/type/ipv4`, then run Moodle's normal upgrade. Teachers choose
one or more of `/8`, `/16`, `/24` and either text entry or four radio choices.
Each attempt saves its generated IP, prefix, mode and answer order in the native
question-engine step. Text answers must be canonical dotted decimal without a
prefix; surrounding whitespace is ignored. Both modes are graded automatically.
English and Russian strings, Moodle XML and course backup/restore are included.
For bulk creation, open the course menu → **Add IPv4 questions to a quiz**,
choose a quiz, count (default 15), prefixes and answer mode, then submit.
Templates are created automatically; concrete exercises are generated per attempt.
Existing questions are preserved; quizzes with student attempts cannot be changed.
Run the Moodle PHPUnit suite `qtype_ipv4_testsuite` after initialising its test DB.
